## Browser extension shared AI interface

The extension bundles and mounts the same `AIChat` component through `browser-assistant-entry.tsx`; there is no second hand-written chat renderer and no website iframe or ordinary `/ai` cookie request. `ai-runtime.tsx` injects the request, streaming, navigation, model-preference and permitted workspace-action boundaries into `AIChat`, `AIProvider` and the pending sender. The normal website retains its API/EventSource behavior. The extension uses only the authenticated `/browser-clipper/assistant/ui` routes, a selected-profile session list, and one default current-page preparation per outgoing message ID. A retained in-memory promise prevents concurrent delivery/retry from preparing a different page for the same message. Preparation failure or cancellation prevents submission. Account/profile revisions remount the client boundary; page and language updates retain the capture map. A pure-memory `compose(text)` handle fills and focuses the existing Sender without sending a model request.

The connection has no arbitrary upload/resource-picker/preferences permissions, so those controls and unauthorized image thumbnails/download actions are omitted in the shared component. Resource/file-folder links open the configured Doca origin; they do not fetch the website’s cookie endpoints from extension origin. The extension project owns the MV3 bundle, ZIP packaging and actual extension-browser acceptance.
