现有外部工具执行器按 MCP requestId 派生内部操作命名空间，用于现有操作 ID。范围路由误把该命名空间当作 `ai_jobs.id`，所以真实 `image_generate` 在供应商请求前报“原始请求不存在”。修复使用独立的真实原任务 ID 查询正式输入；操作命名空间、请求占用和持久回执标识都保持原样。新增回归用例先复现 404，再证明生图、原始候选保存及重复 MCP requestId 拒绝，供应商模拟调用仅一次。

未新增 API/SDK 适配器或持久化业务格式。审计发现的既有历史图片规格默认读取、重试链/检查点读取及缺失 token 计数处理保持现有规则，未删除、改写或迁移；原始厂商 usage 继续完整保留。

- 模型 `doubao-seedream-5.0-pro`，显式规格 `doubao-seedream-5-0-pro-260628`，请求 2731×1536。

## 原生字段对齐与关闭时序

PostgreSQL 完整矩阵暴露真实保存缺陷：assets.purpose 仅 varchar(16)，现有 ai_image_candidate 有 18 字符。用户最终确认仅采用原生字段修改：PG 同类型 varchar 扩宽、默认值和空值约束，SQLite 仅空值约束；SQLite 默认值变化明确拒绝。早期重建表实现已撤回，没有提交或发布，也未用于用户数据库。当前代码不删除/替换业务表、不关闭外键、不写系统 schema。

新库与参考目录同用按引擎生成的最新 DDL：PG 用途长度 32，SQLite 保留原声明 16。旧 NULL 拒绝收紧，不自动补值；默认值修改不触及旧行。类型转换、长度缩小、删改字段、主外键/唯一/CHECK、未知对象和其他不支持差异仍先拒绝，整次事务不留下部分修改；成功后复核并记录当前清单。现有知识册显式离线转换和恢复门槛保留，只同步其参考结构的目标引擎。

实际使用 v0.2.9 发布源码 655e7ecf71274417d2cf5f352f9151612c702859 创建隔离旧库（非运行旧容器镜像），SQLite、PG17/18 的 131 张表全部行哈希保留。PG 目录只允许 assets.purpose 长度 16→32，SQLite 目录完全不变，重复/并发启动通过。独立原生回归验证父子记录、后续默认值、NULL 校验、类型/缩小拒绝、晚期失败回滚，以及 SQLite 表/索引根页和行号不变。内置 SQLite 实测 3.53.4，官方原生 NOT NULL 支持参见 [ALTER TABLE](https://www.sqlite.org/lang_altertable.html)。

首次 PG18 扩展矩阵的 294 项通过，但出现后台任务在数据库关闭后继续查询的未处理异常，该轮整体不通过。新增可控阻塞回归先复现 close 提前完成；修复等待正在领取队列的 pump，再快照并等待 active 任务。任务状态、操作回执及重试语义未变。修复后本地 PG18 矩阵 295 通过、3 项 SQLite 专项跳过，无未处理错误；GitHub PG17/18 和文档检查通过，最终发行头还会重跑。已有保存图片用最终代码再恢复，供应商调用为零、字节哈希一致、旧 504 数据库哈希不变。原生镜像与三个 GitHub 公开附件已全部核验，通过记录见[发行回执](release-0.2.10.md)。
