# Doca 浏览器助手与网页收录设计

日期：2026-10-20  
状态：用户确认后已实现首版（2026-10-21）。实际安装步骤、协议和验收范围见[浏览器助手](../../browser-assistant.zh-CN.md)与[验收记录](../../verification/browser-clipper-2026-10-21/README.md)。本文保留设计依据；“可以/建议”项未全部作为首版承诺。

## 登录方案修订（2026-10-21，用户已确认）

用户明确该功能尚未上线，并要求直接改为跟随当前浏览器的 Doca 登录。以下 v1 激活票据 / 180 天 token 章节保留为设计历史，不作为当前实现约定。当前包只含严格 v2 站点地址配置，支持插件直接编辑服务地址；同源登录页通过单次授权码与随机 verifier 换取绑定网站会话的 10 分钟受限凭证。网站会话和连接状态在服务端逐次复查；插件自动重新验证，退出后失效，撤销后需网站显式恢复。旧 v1 配置与认证拒绝且不转换，原记录、内容和附件保留。新增两张空表，不回填、不改代际。详细行为以[当前使用说明](../../browser-assistant.zh-CN.md)及[登录验收](../../verification/browser-clipper-login-2026-10-21/README.md)为准。

## 1. 已确认的需求

- 在网页选择内容后，在选区上方显示小工具框，点击「收录到 Doca」。
- 点击浏览器扩展按钮，收录当前页面内容。
- 保存位置与策略在 Doca 对应页面集中设置，例如保存到「故障知识库」。初次讨论选定新建文档作为默认；本轮按用户要求扩展为可配置的新建/追加策略，具体策略见下文。
- 图片原文件一起保存到 Doca，不能只保留远程链接。
- 用户从自己的 Doca 平台下载带连接配置的扩展包，安装后不需要再填写站点地址和账户信息。
- Doca 可以生成新配置，用户粘贴到扩展设置中替换连接。
- 面向开源、自部署 Doca，不依赖统一的官方云账户。
- 评估扩展内置 Doca AI 助手，让用户直接用自然语言完成收录、整理和文档操作。
- 用户已要求按方案实现，并增加单个 / 全部插件连接撤销、取消相关 AI 作业、保留已保存内容的机制。

## 2. 首版建议及边界

首版面向桌面 Chrome 和 Edge，采用 Manifest V3。浏览器扩展作为独立客户端开发；Doca 宿主负责账户凭证签发、认证、收录授权和文档保存。这里的浏览器扩展不等于安装在 Doca 插件目录内的业务插件，不能直接获得服务器插件 SDK 的可信服务注入。

整体产品建议命名为「Doca 浏览器助手」，包含快捷收录和 AI 助手两种入口。普通收录不经过模型，收录位置和动作也不依赖模型猜测；用户需要总结、提炼或组织内容时再使用 AI。

### Doca 集中配置「收录方案」

在个人设置增加「浏览器助手」页面，分为「收录方案」「浏览器连接」和「AI 助手」三个区域。知识库页面可以提供「设为收录位置」快捷入口，进入同一份个人收录方案的配置，而不是另存一套知识库级规则。

用户可以创建多个有名称的方案，并选一个默认方案：

| 设置项 | 例子与行为 |
| --- | --- |
| 方案名称 | 故障案例、排查摘录、日常资料 |
| 保存位置 | 个人文档，或故障知识库下的指定父文档/目录位置 |
| 保存策略 | 每次新建文档；或追加到明确选定的已有文档 |
| 默认标题 | 网页标题；可设置日期等明确变量 |
| 来源信息 | 原网页标题、地址、收录时间和收录方式；随内容保留 |
| 图片处理 | 归档原图；不提供默认静默丢图的成功路径 |
| 临时改位置 | 是否允许扩展在本次收录中选择其他有权限的位置；不改变已保存方案 |
| AI 整理偏好 | 可选的默认整理要求，例如故障现象/原因/排查步骤/解决方案；普通收录不自动调用 AI |

例如，方案「故障案例」配置为「故障知识库 / 待整理，每次新建文档」；方案「排查摘录」配置为「追加到故障知识库的〈排查记录〉文档」。扩展默认使用前者，用户也可以一次切换到后者。

配置由服务器保存并执行，扩展内置的连接配置只解决“连接哪个 Doca、使用哪个账户”，不固化目的地和策略。Doca 改方案后，下次收录读取新规则，不用重新下载安装包或重新生成凭证。

准备任务时携带方案 ID 和读取到的 revision；若服务器发现方案已经改变，先提示按新方案重新确认。接受任务后冻结本次已确认的方案快照，之后的目标或策略修改只影响新任务，不能把在途内容悄悄改投其他目录。最终提交仍检查连接、方案启用状态、目标资源和实际权限；停用、撤销或撤权会阻止提交。

### 新建与追加的准确含义

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| 每次新建，推荐默认 | 每次建立独立文档，保存原文、图片与来源 | 故障案例、文章归档，便于独立检索和分享 |
| 追加到指定文档 | 在指定富文本或 Markdown 文档尾部追加一个带标题、时间、来源的完整收录段落组 | 持续积累的排查日志、资料摘录 |

首版不提供自动覆盖已有内容、按 URL 自动替换文档或 AI 自动合并全文。网络重试通过同一请求 ID 去重；用户主动再次收录同一网页是一次新操作，不能只凭 URL 把不同选区或后续补充当成重复内容丢弃。

追加保存时在服务端取得目标当前状态，通过已有协同内容事务插入原生块或 Markdown 增量；不读取整篇后全量覆盖、不把有图片/表格的内容塞入只支持普通段落的 `append.text`。保留目标已有内容、其他客户端的并发编辑、文档谱系和撤销/历史语义。目标删除、撤权、格式不支持或谱系冲突时明确失败，不能自动换成别的文档。

这里的「故障知识库」按普通可编辑知识库处理。若选择的是 Doca 的「知识册」，其成果树按现有规则只读，不能直接新建或追加；应将收录文档保存到普通知识库，再经用户确认登记为知识册来源，交给既有流程生成结果。

### 选区收录

1. 用户在普通 HTTP(S) 网页选择内容。
2. 在选区上方显示「收录到 Doca」及关闭按钮；贴近窗口边缘时调整位置。
3. 点击后保留该次选区快照，显示当前收录方案及其实际位置/策略；打开工具框不应清空原选区。
4. 提供确认收录，以及可选的切换方案、改标题和「交给 AI」；是否允许临时改位置由 Doca 方案控制。快捷收录不要求每次重复填写位置。
5. 保存成功后显示文档链接；提交失败时保留这次待提交内容和请求 ID，允许重试。

工具框使用隔离样式，支持键盘和 Esc。输入框、密码框和正在编辑的 contenteditable 内不自动显示工具框。选区及滚动本身不会上传任何内容。

### 整页收录

点击浏览器工具栏图标，显示当前页面标题、地址、「收录整个页面」、当前收录方案和「打开 AI 助手」。确认后采集当前页面**已经加载的完整 DOM 内容**，包括视口之外已加载的内容；不是只截取一屏，也不是页面截图。

不自动翻页或滚动触发无限加载。虚拟列表中未挂载的内容、跨域 iframe、封闭 Shadow DOM、浏览器内置页面和浏览器 PDF 查看器不能承诺完整收录，需显示范围限制或不支持的原因。正文识别可以后续作为明确命名的独立模式，不能静默把「整页」改成「只保留文章」。

### 内容格式建议

新建时默认创建可编辑的 Doca 富文本文档；追加时按明确目标的富文本或 Markdown 格式写入。保留标题、段落、加粗/斜体、列表、引用、代码、普通链接、基础表格和图片。文档中记录原网页地址、网页标题、收录时间和收录方式。原网页 CSS、脚本和交互组件不进入文档。

图片归档是首版必需能力：扩展读取网页可获取的原图片文件，上传到 Doca，再将正文图片引用改成目标文档的资产 ID。普通位图优先保存原始文件字节，不使用截图代替原图，也不只保存会失效的远程 URL。SVG 等需要按平台安全规则处理的格式明确报告转换情况。音视频首版保存可读标签及来源链接，不承诺完整媒体归档。

- 优先依据实际 `currentSrc`、已解析的图片 URL 和可验证的资源清单获取文件。页面缩略图无法访问其全尺寸版本时，不宣称已取得更高清原件。
- 来源站点如需要会话，扩展仅在浏览器允许和相应站点权限范围内读取，来源 Cookie/令牌不传给 Doca，也不注入上传文件元数据。
- 使用 Doca 的文件存储、内容识别、附件体积和权限规则，绑定到最终新建或追加的目标文档。相同图片的文件复用不得复用别的文档资产 ID 或绕过 ACL。
- 图片先暂存，全部校验通过后再完成正文保存。失败显示具体图片和重试入口，默认不显示“完整收录成功”；仅用户明确选择接受缺失时才保存缺失说明。
- 不让服务器直接抓取任意图片地址来绕过来源站点限制，不宣称所有登录图片、临时 blob、跨域图片或未加载图片必定可读。

建议在宿主增加有明确归属和回收规则的收录暂存流程：先登记任务和上传原图到受控暂存对象，最后在一个数据库事务内创建资源、登记目标资产、一次性初始化正文和记录成功回执。追加则在事务内登记目标资产、提交协同增量并记录回执，提交后再广播。普通资产接口目前要求所属资源，不能假装它已经支持无资源暂存；需要实现对应宿主服务，不借用 AI 附件目的类型冒充收录暂存。

网络文件上传不放在数据库长事务中。未成功收录的暂存任务按明确的有效期和状态回收；已经绑定到文档的图片不随连接撤销、临时任务清理或配置替换而删除。外部对象写入失败不能产生虚假的成功回执。

## 3. 安装与下载

### 自部署下载模式

在上述「浏览器助手 → 浏览器连接」页面提供创建连接、下载扩展、生成替换配置、撤销连接和安装说明；收录方案和 AI 开关在 Doca 配置。

服务端以统一、已构建的扩展文件为模板，按当前用户生成 ZIP，仅加入当前部署的地址和一次性激活配置。打包不能执行用户提供的代码，也不能把用户配置写回共享模板或共享缓存。

首次使用路径：

1. 用户登录自己的 Doca，创建一个有名称的浏览器连接并下载 ZIP。
2. 解压文件，在浏览器扩展页开启开发者模式，选择「加载已解压的扩展程序」。
3. 扩展首次启动，读取内置配置并完成激活，显示实际站点和账户。
4. 用户可以直接收录；不另行输入密码或站点地址。

Chrome 的普通 Windows/macOS 安装不能把个人站点下载的 CRX/ZIP 当作商店扩展直接安装。下载时必须说明开发者模式步骤，不能宣传「下载后双击安装」。Edge 官方也提供开发者模式加载已解压扩展的流程。

官方依据（2026-10-20 阅读）：

- [Chrome：Alternative extension distribution options](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions)
- [Edge：Sideload an extension](https://learn.microsoft.com/en-us/microsoft-edge/extensions-chromium/getting-started/extension-sideloading)

### 后续商店分发

商店发布统一扩展，Doca 继续提供个人配置。每个用户不能从商店下载不同字节的个人包。通过配置导入或另行设计的一次授权流程连接自部署站点。首版不把商店审核、自动安装或自动更新作为已交付能力。

## 4. 凭证与配置替换提案

### 独立的收录身份

不导出网站登录 Cookie、手机 Bearer 会话或 MCP token。新增独立浏览器连接凭证，按 Doca 页面上用户启用的能力使用：

- 基础收录：读取方案与非敏感位置概要、上传本次图片、按已确认方案新建或追加、读取本次收录结果。
- 可选 AI：启用后才允许创建/继续该连接关联的个人助手会话、发送明确选择的网页上下文及使用授权的文档工具。
- AI 的资源范围和工具范围由服务端执行；默认围绕本次材料和方案目标，需要更广知识库范围时由用户明确选择。不可只在扩展界面隐藏按钮，却让服务端接受任意工具调用。
- 不授予管理后台、权限修改或通用网络代理能力；新增工具不能因为“启用了 AI”就自动进入连接授权。

每次请求和 AI 工具执行时重新检查用户状态、资料补全要求、创建/导入/上传能力、目标资源权限及平台准入规则。凭证声明的范围不扩张用户本身的权限；设置收录方案也不能让其他用户获得该知识库权限。个人文档建议按私有方式创建；知识库位置明确展示其继承可见性，遵循现有目录权限。

每个浏览器安装建议使用独立连接，支持单独撤销；下载另一个设备的包不会撤销原设备。

### 下载包内的凭证

建议内置**30 分钟有效、单次使用的激活凭证**，而不是长期访问密钥。首次激活后换取 180 天有效的专用收录密钥。服务端只保存随机密钥的哈希；实际密钥只在签发时交给扩展，不写 URL、审计详情或日志。

激活配置示意（完整字段以当前接口的严格 v1 校验为准）：

```json
{
  "version": 1,
  "origin": "https://doca.example.com",
  "connectionId": "<UUID>",
  "activationId": "<UUID>",
  "activationSecret": "<random secret>",
  "expiresAt": "<ISO timestamp>"
}
```

生产连接使用 HTTPS；开发仅允许明确的本机回环 HTTP 地址。配置不接受 URL 中的用户名密码、任意 API 路径或重定向后的其他站点。

同一激活凭证不能绑定多个安装。激活超时、失效或因响应丢失不能完成时，显示可操作错误，在 Doca 重新生成配置；不能偷偷创建另一个账户会话或恢复旧凭证。

上述有效期均为建议值，尚未获得用户对凭证生命周期的确认。

### 粘贴替换

1. Doca 为指定连接签发新的待激活配置；此时该连接当前密钥继续有效。
2. 扩展设置提供「粘贴 Doca 配置」，校验全部必需字段并显示目标站点。
3. 如需访问新站点，在用户点击导入时申请该站点权限。
4. 完成目标站点校验与激活后，才提交新连接的本地配置。
5. 同一连接的密钥轮换在服务端原子撤销旧密钥；激活前的失败不能导致旧连接失效。
6. 切换到另一站点或账户时，隔离原连接的方案、待提交内容及 AI 对话视图；待提交内容不得自动发往新连接。旧站点连接由用户在旧站点管理撤销，不能假装本地替换已撤销远端授权。

若服务端激活成功而本地持久化失败，明确报告需要重新生成配置；不宣称这时旧密钥仍有效。已收录的文档不受凭证轮换或撤销影响。

扩展密钥只保存在受信任扩展上下文可访问的本地存储，不使用浏览器同步存储。网页内容脚本只接触待收录内容和非敏感状态，不能读取密钥。凭证请求由后台发出，后台不接受来自网页的任意目标 URL 或任意 HTTP 请求代理。

## 5. 服务与存储提案

### 待新增接口

以下路径和字段均为提案，不能在实现前视为现有公开能力。

| 路径 | 认证和作用 |
| --- | --- |
| `GET/POST /api/v1/me/browser-clipper/profiles` | 网站会话；列出/创建个人收录方案 |
| `PUT /api/v1/me/browser-clipper/profiles/:id` | 本人、当前 revision；更新目标、策略和明确选项 |
| `GET /api/v1/me/browser-clipper/connections` | 现有网站会话；列出本人的连接，不返回密钥 |
| `POST /api/v1/me/browser-clipper/connections` | 现有网站会话和同源写校验；创建连接及首次激活配置 |
| `POST /api/v1/me/browser-clipper/connections/:id/config` | 本人、当前 revision；为该连接生成替换配置 |
| `POST /api/v1/me/browser-clipper/connections/:id/revoke` | 本人、当前 revision；撤销连接及未使用激活凭证 |
| `POST /api/v1/me/browser-clipper/connections/:id/download` | 网站会话和同源写校验；生成包含激活配置的个人 ZIP，不缓存响应 |
| `POST /api/v1/browser-clipper/activate` | 独立的激活凭证校验；单次兑换，不接纳网站 Cookie 作为授权依据 |
| `GET /api/v1/browser-clipper/me` | 独立连接密钥；返回站点、账户概要和启用能力 |
| `GET /api/v1/browser-clipper/profiles` | 独立连接密钥；返回本人收录方案和 revision |
| `GET /api/v1/me/browser-clipper/destinations` | 网站会话；配置方案时按当前权限分页查询位置概要，不返回正文 |
| `/api/v1/browser-clipper/clips` 及其任务/图片子路由 | 收录权限；准备任务、上传图片、查询进度和确认提交新建/追加，分步骤请求使用同一请求 ID |
| `/api/v1/browser-clipper/assistant/*` | 已启用 AI；有限的会话、消息、事件、附件、审批和取消接口，不是普通 AI 路由任意透传 |

不会为扩展开放通用浏览器跨域会话认证。中央 Origin 检查如需增加入口，只允许这些明确的独立认证路由；管理接口继续使用现有 Host、Origin 和会话校验。扩展请求不携带网站 Cookie，也不能通过扩展凭证进入普通原生 Bearer 会话路径。

收录请求包含明确的 `version: 1`、客户端生成的 `requestId`、选区/整页 `mode`、`profileId`/`profileRevision`、网页标题和原始地址、收录时间、可编辑标题、规范化内容及图片清单。仅方案允许时接受本次位置覆盖。服务端从凭证确定用户和能力，从已确认方案确定策略与位置，不信任客户端提交的 owner、ACL、权限声明或任意原生编辑器节点。

扩展从 DOM 提取可移植内容，宿主校验并转换到当前已安装编辑器的原生模型，再调用现有资源创建/初始内容导入流程。已核实当前安装的 `@smartdoca/slate@0.4.23/conversion` 导出 `importMarkdown`；实际模型、警告和资源回调应按该包声明实现并做真实往返验收，不假设存在 HTML 导入接口。

先对源内容、节点数、深度和最终模型体积设置明确限制；当前富文本初始导入上限为 768 KiB，Markdown 路径为 512 KiB。超过限制时明确失败，不能静默截断后返回完整收录成功。

内容导入/追加、资产归属与成功回执在同一事务内提交，收到已提交回执才显示成功。重试沿用原请求 ID 和原参数；同一用户/请求 ID、同一摘要返回原结果，不重复新建或追加。相同 ID 不同内容返回冲突。原结果删除或不再可访问时返回明确错误，不能借重试重新创建文档。

追加复用底层内容验证、持久提交及提交后广播能力。当前 `editAIDocument` 已经经过 `createDocuments(...).exchange` 保存增量，但还带有 AI 任务上下文和 AI 操作回执；实现时应明确提取可复用的宿主文档能力，不能伪造 AI 作业来调用内部函数，也不能把 HTTP 初始导入接口改成已有文档全量保存入口。

影响范围是当前工作树 Doca `0.2.6` 及尚未包含浏览器收录接口的部署，数据库兼容代际为 `doca-2026-10-12-book-payload-storage-v1`。新增浏览器配置和接口都是首个协议版本；当前仓库没有可迁移的旧收录配置或旧收录凭证。

| 对象 | 拟定处理 |
| --- | --- |

| 现有文档、资产、权限、会话、MCP 配置 | 保留原始内容和原有行为；不转换为收录数据，不把旧凭证升级成收录凭证 |

| 已完成新功能升级后的应用降级 | 不承诺旧程序可以启动含新表数据库，不删除新表或回执来强行启动；保留数据库、文件及新增记录后另行审批恢复方案 |

既有兼容代码审计：宿主目前仍有手机 Bearer 会话及续期路径、受限插件 WebView 会话、独立 MCP v1 认证。数据库协议记录了保留但不再作为当前 MCP 凭证读取的 `ai_mcp_keys` 旧表，以及已有历史存储/知识册升级门禁。它们不属于本功能的重新设计范围；本方案不删除、迁移或把它们作为收录功能的兼容分支。

升级前备份数据库与文件卷。升级失败时结构调整和 footprint 记录全部回滚；升级成功后的恢复必须保全新文档和新凭证记录，恢复旧备份会丢失后续写入，不能作为自动回滚操作。服务端和 Web 一起更新；扩展按明确协议能力判断可用性，不以产品版本字符串猜测接口。

用户已同意新增表并说明目前没有旧收录凭证问题，不再把“迁移旧收录凭证”作为待办。本轮按“先看看方案”只更新设计；尚未修改最新 DDL、`schemaEvolution`、Kysely 类型或持久配置读写行为。新增的方案、助手授权及暂存格式仍需在方案确定后按此范围落实，不把新增表的同意扩大为历史文档转换许可。

## 7. 扩展内置 Doca AI 助手

### 用户体验

建议使用浏览器侧边栏承载对话，保留当前网页。扩展小弹窗负责快捷收录和打开助手；AI 不挤进短暂的小弹窗。侧边栏提供对话、当前网页/选区上下文、当前收录方案、执行进度和文档结果卡片。

可以直接说：

- 「把这段内容保存到故障知识库，图片也保存。」
- 「按故障现象、可能原因、排查步骤和解决方案整理这篇文章，先给我看一下。」
- 「把刚才的内容追加到排查记录。」
- 「在我允许检索的故障资料里查找相似问题，比较解决方法。」

用户点击「交给 AI」或明确附加「当前页面/当前选区」后才把内容发送给 Doca 和配置的模型服务。普通浏览、选区变化和切换标签页不自动上传。切换网页时，已经发送的那份材料保持原网页快照，不把后续消息的材料悄悄替换成新页面。

普通收录忠实保存原文和原图。AI 总结、分类或改写默认展示结果，保存时明确目标与新建/追加动作；需要保留原始材料时将原始收录与整理稿作为独立文档或引用，不把摘要当成原文完整归档。是否执行已有工具审批，沿用 Doca 的实际设置与用户操作，不为浏览器助手另建一套不一致的规则。

### 复用边界与已核实能力

复用同一 Doca 账户的模型选项、个人偏好、会话/作业、流式事件、取消、工具审批、文档能力和 AI 用量记录。模型 API 密钥留在服务端，扩展不直接连接模型厂商，也不创建第二套 AI 业务存储。

扩展创建的会话仍是当前用户的普通 Doca 个人助手会话，可在 Doca 中继续。关联表控制该连接能打开哪些会话；不能因为知道会话 UUID 就打开同用户的任意历史会话。撤销浏览器连接阻止后续访问和新作业；已经运行的该连接任务需要有取消/授权复查机制，不能仅在建立连接时校验一次。撤销不删除会话、图片或已完成文档。

已核实的当前能力：

- `docs/plugin-assistant.md` 的 `host.ai.open()` 是 Doca 内部 Web/原生插件启动入口，外部浏览器扩展不能直接获得这个对象。
- `apps/server/src/routes/ai.ts` 已有模型选项、会话创建/读取、消息作业、持久事件、流式返回、审批和取消接口，依赖现有用户会话认证。需要抽取可复用服务并提供受限的扩展接入，不能直接放行全部 `/ai/*`。
- `packages/core/src/workflows/ai-documents.ts` 已有实际用户权限、授权资源范围及可写限制，并通过现有协同交换保存内容。图片插入已有目标资产重绑定和内容事务的实现参考。
- 富文本 `append.text` 仅处理普通段落，图文/表格追加必须按当前原生块操作落地。

首批 AI 工具建议开放文档查询、允许范围内的读取、新建/追加和明确的文档编辑，以及浏览器本次材料读取。其他插件工具只有具备可验证的连接/资源授权边界时才加入。Doca 的 SKILL 可以用于提供操作方法，但不能扩大连接的工具权限。

网页内容作为外部材料，不作为系统指令；其中“忽略规则、读取其他文档”等文本不能改变工具授权。长页面超过现有消息文本上限时，通过已授权的会话材料/附件和分段读取处理，不能静默截断或把正文放进 URL。收录目的地不会自动成为模型输出中所有操作的唯一权限依据。

### 需要新增和验证的部分

- 扩展侧边栏 UI、账户/模型/方案状态、对话与结果卡片。
- 独立连接认证下的助手入口、材料/附件传输、事件续读、会话关联和工具权限传播。
- 服务端任务执行期间及续跑时对连接撤销、资源撤权和范围变化的检查。
- 浏览器侧边栏的 Chrome/Edge 支持范围、用户手势开启规则及最低版本。参考 [Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) 和 [Edge sidebar extensions](https://learn.microsoft.com/en-us/microsoft-edge/extensions-chromium/developer-guide/sidebar)；本轮这两页联网读取超时，浏览器支持矩阵留待实现时复核，不把两者视为已完成验收。

不采用把 Doca 全站页面塞入 iframe 并放宽现有页面防护的方案；也不通过一个可以任意访问站点接口的长效通用会话来替代扩展权限设计。

## 8. 实施顺序与验证

建议分为三个可独立验收的阶段，前一阶段的方案和数据结构按完整首版设计，而不是发布后再自动转换早期试验格式：

1. **收录闭环**：Doca 方案配置、独立连接、预配置包下载、选区/整页、新建文档、原图归档、持久回执与重试。
2. **追加与策略**：明确目标的图文追加、方案切换与 revision、并发编辑/重试不重复，以及目录和知识册边界。
3. **内置助手**：侧边栏、同一 Doca 个人会话和模型、网页材料、文档工具、审批/取消/断线续读及授权限制。

建议浏览器客户端放在 `apps/browser-extension/`，统一构建为服务端可打包的静态模板；宿主设置页面和接口分别放在 Web、Server 的对应功能模块。以实际构建/部署脚本验证模板进入源代码运行和部署包，不能依赖开发机目录。

实施遵循仓库的协同、编辑器集成、文件交换、界面语言和数据库演进约定。新界面使用稳定英文 key 和中英目录，语言变化不触发文档重建。已存在的用户工作区改动不属于本功能。

验收至少包括：

- Chrome/Edge 实际加载下载包，首次绑定、有效期、粘贴替换、账户切换、连接撤销和安装步骤。
- Doca 修改方案后下一次收录读取新规则；在途方案变化、临时位置覆盖、默认方案切换和目标失效不静默改投。
- 选区工具框位置、长页面、基础富文本/表格、中文、源地址解析、失败重试；明确验证支持与不支持的 DOM 范围。
- 原图片文件归档、页面关闭/原站图片失效后仍可按 Doca 权限访问；图片失败、超限和中断时没有虚假完整成功；暂存清理不删除已绑定图片。
- 激活单次消费、重复/并发兑换、过期、轮换 revision 冲突、响应或本地持久化失败及无密钥日志。
- 禁用用户、资料补全、目录撤权、知识册成果目录拒绝、跨用户连接、错误 Host/Origin 和普通接口拒绝收录凭证。
- 脚本/事件属性、危险链接、伪造资产和原生模型注入、内容超限及失败不残留成功回执。
- 同一请求并发与重放只新建/追加一次，提交后响应丢失可恢复，原结果已删除不重建；多人同时编辑时追加不覆盖已有内容。
- 新建文档进入现有编辑器后可编辑、重载及双客户端同步；原有文档和协同 outbox 不被改写。
- 助手使用现有个人会话/模型及实际用量，浏览器材料发送范围明确；关闭侧栏不丢已持久事件，重复发送不重复执行，其他连接/账户不能读取该会话。
- AI 实际调用中的资源范围、撤权、连接撤销、审批和取消；网页指令不能扩大工具权限；未启用 AI 的凭证不能访问助手入口。
- 使用隔离 SQLite、PostgreSQL 17/18，验证带旧行数据库的空表增量、重复/并发启动、未知差异拒绝且无部分写入。
- 发布前由实际已发布旧版本建立隔离数据，再运行新版本升级；记录保留数据及具体版本/引擎的结果。

当前仅完成仓库与官方安装限制的只读调查，以及本文设计。以上功能、测试和升级验收尚未执行。
