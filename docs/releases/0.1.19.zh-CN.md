# Doca 0.1.19

[English](0.1.19.md)

本版修复 Meilisearch 搜索索引重建，并提供无需业务服务器访问 GitHub 的部署交付方案。插件 SDK 保持已发布的 0.1.10。

## 改动

- Meilisearch 向量请求的临时错误不再被当作索引任务的最终失败；等待已提交任务完成，避免重复提交仍在处理的任务。超时保留脱敏后的诊断。
- 已存在的活动索引通过独立版本重建，所有任务成功后再原子切换；首次重建失败时保留原索引及查询能力。
- 管理后台分别显示重建失败和自动同步失败，逐项列出失败的来源及原因，隐藏错误中的 Bearer 和 API 密钥。
- 新增双语部署指南，提供可复制的 Compose 和 `.env`、初始化与管理员密码恢复流程，以及 Docker Hub 拉取和离线镜像交付两种方案。
- `node scripts/pack-deployment.mjs` / `pnpm deploy:pack` 生成仅使用镜像的部署包和 SHA-256 校验文件，包含环境变量示例、Chromium seccomp 策略及管理员脚本，不包含工作区秘密或用户数据。正式 Release 自动附上部署包。管理员初始化和密码恢复显式使用本机镜像，不尝试在线拉取。

## 验证与发布

冻结依赖安装、TypeScript、Web 构建和 57 篇双语文档检查通过。全量测试共 268 个文件通过，2,654 项通过、3 项环境测试跳过。SDK 制品核对与最终镜像检查结果记录在发行验证附件。所有部署验证使用隔离的数据库、持久卷和测试账号。

- GitHub 标签 `v0.1.19`，附 Web 资源、部署文件包、校验和与验证记录。
- Docker `docker.io/smartdoca/doca:0.1.19` 与 `latest`，Linux amd64、arm64。
- 插件 SDK `@smartdoca/plugin-sdk@0.1.10` 的 JavaScript、类型声明和导出与 npm 制品一致，本次搜索与部署改动无需新的 SDK 接口。依赖 `web-plugin-registry@0.1.3` 存在此前未发布的内置导航差异，核对结果见发行验证附件。

## 部署与回退

数据库基线仍为 `doca-2026-10-09-history-storage-v1`。本次没有新增旧格式适配、数据库迁移或用户数据转换；已存在的严格基线校验和显式历史升级命令未修改。

0.1.18 部署更换镜像时保留原数据库、文件、配置、Compose 项目名和 `DOCA_CREDENTIAL_MASTER_KEY`。更早基线遵守 [0.1.15 升级要求](0.1.15.zh-CN.md)。回退前停止写入并备份数据，原发行制品和标签保留。离线交付步骤见[无需访问 GitHub 的部署](../deployment-without-github.zh-CN.md)。

应用健康不能代替目标宿主机的渲染器验收。外部 AI、身份服务、插件和云存储仍需业务网络可达；本版不包含这些服务的部署。
