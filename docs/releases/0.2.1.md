# Doca 0.2.1 — Title icon editing and quieter access tags

[简体中文](0.2.1.zh-CN.md)

Access tags now use pale backgrounds and darker text, with red, blue and green retaining their Private, Collaborative and Public meanings. Tags beside home-page and top-left document titles are smaller. Document lists retain a separate Access column; permission calculations and rich-text body heading styles are unchanged.

When editing a title with an emoji prefix, the icon appears only in the selector while the text field shows the title text. Changing, removing or manually entering an emoji still saves one complete title string. Form submission includes the selected prefix, and choosing an icon before entering a new title retains that choice. Opening and confirming an unchanged title preserves its original spacing without a write.

The rich-text toolbar includes all 24 common title icons alongside its existing emoji, without duplicates. Both controls share one list. Body text and body headings use native Unicode text insertion and the existing collaboration commit path.

Library creation and renaming use the same title control. Library cards and home show the leading emoji as their icon without repeating it in the text; removing it restores the original library icon.

## Upgrade and recovery

Update server and Web together. The release integrates official npm Canvas 0.5.5, which removes the code-block menu action and scopes inline/suggestion CSS to the canvas root. Its public exports, declarations, dependencies and model/codec bytes match 0.5.4. Slate remains at 0.4.23 with its existing patch. It adds no SDK interface, temporary archive dependency, database structure change, migration or backfill. Existing titles, content, history, checkpoints, epochs and pending updates remain intact; explicit edits use the established title string and native operations. Retain the 0.1.32 deployment, lockfile and data backup. Rollback restores the earlier UI; preserve subsequent writes.
