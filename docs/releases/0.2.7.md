# Doca 0.2.7 — Browser assistant and document operations

[简体中文](0.2.7.zh-CN.md)

The browser assistant captures selections or loaded pages with original images and provides AI conversations. Configure destinations and create/append profiles in Doca. Downloads contain a site address only; the extension uses this browser's Doca sign-in, opens a normal login page when needed and reauthorizes short-lived access automatically. Edit the server address directly or paste public site configuration. Website logout invalidates associated access. Revoke individual/all connections without deleting content; restoration requires an explicit action in Doca.

This release also includes the current workspace's tree-based move destinations, copy destination/hierarchy/permission fixes, company MCP navigation, and Canvas 0.5.8 / Sheet 0.2.5. Canvas images use a lightbox with zoom, navigation, download and copying; editor updates improve connector movement, native-filter synchronization and related undo/readonly behavior. See [editor acceptance](../verification/editor-packages-2026-10-21/README.md) and [browser assistant acceptance](../verification/browser-clipper-login-2026-10-21/README.md).

## Upgrade and recovery

The schema generation is unchanged. Current DDL and reconciliation add seven empty browser-assistant tables without backfilling historical authorization or rewriting documents. Isolated SQLite / PostgreSQL 17/18 databases created by released 0.2.6 retain hashes of 124 original tables through repeated/concurrent startup. Prelaunch v1 extension configuration and 180-day credentials are rejected without conversion; retained development records/content remain, and the updated extension signs in using its site address.

Back up databases, file volumes, settings and the original credential master key; update server, Web and extension together. Production extension origins require HTTPS; loopback HTTP is supported for local development. Extract the extension and load it through Chrome/Edge developer mode; store-signed distribution is not provided. Brand-browser native sidebars, actual model vendors and real-site authenticated-image behavior still require deployment-specific acceptance. Chromium automation and simulated models do not establish those results.

Downgrade needs a separately reviewed preservation plan. Do not remove tables or restore the old v1 authentication entry point. Prior shared-plugin-business-database requirements remain in the [0.2.5 notes](0.2.5.md#upgrade-and-recovery).

Compose pins `docker.io/smartdoca/doca:0.2.7`. The GitHub Release includes corresponding Web assets, an image-only deployment bundle and checksum; Docker Hub supports Linux amd64 / arm64. Concrete build/publication evidence is recorded in [release verification](../verification/release-0.2.7/README.md).
