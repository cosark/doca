# Doca 0.2.10 — 图片任务与原生字段对齐

[English](0.2.10.md)

MCP 生图原先把内部操作命名空间当作正式用户任务查询，在调用图片厂商前就返回 404。现在范围校验读取真实且属于当前账号的原任务；操作 ID、请求占用、最多执行一次规则、用量记录和文档格式保持原样。

使用 Doca 现有 Seedream 适配器，已验证火山 Agent Plan 直连：地址 `https://ark.cn-beijing.volces.com/api/plan/v3`、模型 `doubao-seedream-5.0-pro`、显式规格 `doubao-seedream-5-0-pro-260628`。隔离任务仅提交一次，在 63.354 秒后收到 HTTP200，保存 2731×1536 UI 位图及原始候选。另一个进程重开数据库后，可复用同一保存回执和图片字节，供应商调用为零，call/operation/asset 行不变。这支持绕过此前中间层的 60 秒截断；线上具体网关超时配置尚未核实。

此前 HTTP504 是独立的原请求：仍无返回图片、用量未知，原 call/operation 保留，不自动重试或对账。本轮未修改生产模型配置，代码及发布制品不含 API Key，所给密钥仅在内存中用于请求认证。

类型检查、生产构建和 MCP/重试/范围针对性检查通过。两轮完整测试分别通过 3334 项、各有一个不同的既有下载/图像用例超时；两个用例单独复跑均通过，不宣称存在单轮全量全绿结果。原生 amd64/arm64 镜像验收和公开发布回执在通过后补齐。

修复 PostgreSQL 生图原始候选保存：assets.purpose 从 varchar(16) 扩为 varchar(32)。启动支持已确认的原生字段对齐：PostgreSQL 同类型 varchar 扩宽、默认值和空值约束；SQLite 仅空值约束。旧行存在 NULL 时拒绝改为必填，修改默认值不补写或覆盖旧行。SQLite 默认值变化、类型转换/缩小、删除字段及主外键/唯一/CHECK 变化仍使整个事务停止。不重建表、不修改系统表、不自动降级。已发布 0.2.9 源码创建的 SQLite、PG17/18 库均保留 131 张原表哈希，PostgreSQL 结构仅用途长度扩大。部署前请阅读[升级规范](../database-schema-evolution.zh-CN.md)，备份并统一更新全部宿主。

关闭服务时会先等待正在进行的队列领取，再等待执行中的任务结束，避免后续访问已关闭数据库。现有任务状态、回执和重试规则保留，不改变 SDK、浏览器偏好或队列格式。继续遵循 [0.2.8 升级/恢复要求](0.2.8.zh-CN.md)，保留全部数据及部署主密钥。详见[直连与恢复核验](../verification/ui-image-ark-plan-2026-10-23.md)、[Web 镜像层实测](../verification/image-web-layers-2026-10-23.md)。
