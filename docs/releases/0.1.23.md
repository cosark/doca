# Doca 0.1.23

[简体中文](0.1.23.zh-CN.md)

This release integrates `@smartdoca/slate` 0.4.14 and `@smartdoca/canvas` 0.4.3, publishes plugin SDK 0.1.11, and includes the pending knowledge-book reliability, private payload storage, monitoring and cached-document startup changes.

Slate adds native shapes, filled arrows, editable manual routes and endpoint anchors, compact diagram text editing, and code/media interaction improvements. AI creation accepts the shipped shape and geometry fields and preserves them when changing a diagram. The existing DOCX conversion patch is applied to the new artifact. Canvas updates native text styling with the same public model, codec and IO entrypoints.

The agreed editor upgrade adds no old-flowchart adapter or automatic node conversion and makes no old-flowchart compatibility promise. Original checkpoints, increments, comments and pending message IDs are retained. New diagram fields use the shipped native model. A previous editor may not render them correctly; preserve the previous deployment and pre-upgrade backup. This is separate from the explicit knowledge-book database upgrade below.

SDK 0.1.11 exposes `monitoring.v1`, `telemetry.v1` and administrator Web monitoring transport. Existing contract-package versions remain unchanged. Knowledge-book runs now recover notifications independently, stop taking concurrent resume work, read large results lazily, and retain stable Mermaid previews. Cached authorized documents restore before network discovery and retry their original pending updates after reconnect; a prior live open and available application assets/browser storage are required. This does not provide a complete offline application shell.

## Existing deployments must upgrade storage explicitly

The target database generation is `doca-2026-10-12-book-payload-storage-v1`. Normal startup rejects the released 0.1.22 generation without changing it. Stop all hosts, back up SQL/private objects/configuration and keep the original credential key, store IDs and deployment identity. Use the new image with the existing deployment environment:

```sh
docker compose stop
docker compose pull
docker compose run --rm --no-deps doca node --import tsx apps/server/src/bootstrap/knowledge-book-storage.ts upgrade
docker compose run --rm --no-deps doca node --import tsx apps/server/src/bootstrap/knowledge-book-storage.ts upgrade --apply --hosts-stopped --manifest /data/book-upgrade-0.1.23.json
docker compose up -d
```

Only the exact preceding `doca-2026-10-09-history-storage-v1` generation is supported by this conversion. Earlier generations first follow their separately approved history upgrade. The new command preserves original JSON bytes in verified private compressed objects before installing strict SQL references; it does not infer historical values, dual-read old formats, reset data or automatically vacuum SQLite. Update all host and Web builds together.

Interruption requires resuming the same explicit command and manifest. Before returning to 0.1.22, stop all writes and perform the new image's explicit storage rollback with a new persistent manifest; rollback restores post-upgrade outcomes too. Do not start an old image against the new database. See [storage verification and recovery](../knowledge-book-storage-verification.md) and [database evolution](../database-schema-evolution.md).

## Artifacts and verification

GitHub tag `v0.1.23` includes Web assets, deployment files, plugin SDK tarball, checksums and release verification. Docker tags are `docker.io/smartdoca/doca:0.1.23` and `latest`, for Linux amd64 and arm64. npm publishes `@smartdoca/plugin-sdk@0.1.11`; the host itself is private and is distributed through GitHub and Docker Hub.

The release verification attachment records final full-suite/type/build/docs results, native diagram ACK/replay/undo/checkpoint tests, isolated browser checks, SDK registry-consumer imports, PostgreSQL 17/18 tests and both image architectures. Retained actual-0.1.22 fixtures verify byte-exact storage upgrade/rollback on SQLite and PostgreSQL 17/18. All checks use synthetic accounts and isolated data. Production S3 credentials, external AI providers and native mobile devices are outside this verification.

Canvas 0.4.3 also contains a user-approved view rule: numeric text line heights from 0.8 through 3 are displayed as font-size multipliers; other numeric values remain pixels. Loading, selection, resize and idle do not rewrite the model. Ordinary text editing preserves the original numeric field; an explicit line-height edit stores the native percentage value. No host migration, backfill or stored-data deletion is added. Browser acceptance verifies 1.5 at 32 px as 48 px, original numeric bytes after text edits, no idle writes, peer convergence and reload. Previous UI rendering is not guaranteed on rollback.
