# Doca 0.1.24

[English](0.1.24.md)

0.1.24 让已发布 0.1.22 的旧库直接在启动时对齐最新结构，无需执行知识册存储维护命令。沿用最新 DDL 和结构对比器，在同一 schema 锁事务中补齐已审定的新表、复核结构、记录 footprint 和目标代际。

按用户最终确认的方案，全部业务记录原样保留，包括旧 SQL 知识册生成成果、运行、人工待办和发布指针。不新增单独清理、自动正文转换或旧正文读取适配；新成果使用新版原生对象存储。旧记录可能需要人工处理后才能使用相应知识册。已升级到 0.1.23 的对象、引用和成果保持完整。

## 已有部署升级

停止全部旧宿主，备份数据库、私有存储和配置，保留原凭证主密钥、存储 ID 及部署身份，更新到本版本后启动即可。所有宿主和 Web 构建一起更新。

```sh
docker compose stop
docker compose pull
docker compose up -d
```

自动结构对齐只支持准确的前代 `doca-2026-10-09-history-storage-v1`，目标为 `doca-2026-10-12-book-payload-storage-v1`。更早代际仍须完成各自已批准的历史存储升级；未知代际、转换中断或需审查的结构差异继续停止且不产生部分修改。代际记录目标结构，不代表残留旧 JSON 已转换成可读成果。不自动 VACUUM，不删除未知业务表。

既有可选无损知识册维护命令保留，需把旧成果继续保留为新版可用格式时，应在首次启动 0.1.24 前执行；结构对齐后转换的源代际不再匹配。见[维护与恢复](../knowledge-book-storage-verification.zh-CN.md)。回退保留全部数据及后续写入，旧宿主不能直接使用目标代际。

## 发布与验证

延续 0.1.23 的 Slate 0.4.14、Canvas 0.4.3 对接和已发布的插件 SDK 0.1.11；SDK 内容不变，无需重复 npm 发布。宿主是私有 npm 项目，通过 GitHub 与 Docker Hub 分发。

GitHub `v0.1.24` 附带 Web 资源、部署包、校验和及发行验证记录。Docker `smartdoca/doca:0.1.24` 和 `latest` 支持 Linux amd64、arm64。发行验证记录包含 SQLite、PostgreSQL 17/18 的自动结构对齐、全行保留、失败回滚、重复／并发启动、原生对象读取，以及实际 0.1.22 镜像生成的隔离旧库和双架构镜像检查。全部使用合成数据，未操作用户文档或生产数据库。
