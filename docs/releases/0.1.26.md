# Doca 0.1.26

[简体中文](0.1.26.zh-CN.md)

Plugins now share one business database, separate from core. Adding a plugin automatically creates its namespace and declared tables; administrators no longer create a database/account for each plugin.

## Configuration

SQLite automatically uses `<DOCA_SQLITE_PATH>.plugins.db`, optionally overridden by `DOCA_PLUGIN_DATABASE_PATH`. PostgreSQL requires one shared database and restricted role configured through `DOCA_PLUGIN_DATABASE_URL`. All plugins share one pool per instance, limited by `DOCA_PLUGIN_DATABASE_POOL_MAX` (default 4, range 1–20). PostgreSQL isolates plugin schemas; SQLite prefixes physical table names. Public SDK APIs and SDK table names are unchanged, so no npm package release is required.

Uninstall removes only that plugin's declared tables and private data, retaining other plugins and the shared store. Missing stores/namespaces/tables, mismatched markers and unexpected structures are rejected without silently rebuilding business data. See the [storage contract](../plugin-database-isolation.md).

## Required upgrade from 0.1.25

**Normally uninstall all external business plugins on 0.1.25 before stopping and updating the host.** The approved policy discards plugin private business rows, encrypted credentials and private objects without migration. Reinstall and reconfigure/rebind accounts afterwards. Core users, documents, permissions, ordinary user files and the original credential master key remain.

Back up core, old plugin databases/files, private file storage and configuration first. Resolve old-host uninstall/cleanup failures before upgrading. Stop every instance, remove `DOCA_PLUGIN_DATABASES_JSON` / `DOCA_PLUGIN_DATABASE_DIR`, configure the shared store, deploy, reinstall and restart all instances. Active format-2 installations and obsolete settings are explicitly rejected. New declarations use host format 3. No old-store reader, automatic migration or old-database deletion is provided. Core DDL and `schema_baseline.id` remain unchanged; older schema/history/book upgrade gates still apply.

Retain matching original backups and the old deployment for recovery before new writes. After new writes, preserve new databases/files and obtain a separate recovery decision; old backups would lose later data. Old hosts cannot read format 3, and mixed old/new operation is unsupported. See [exact steps and recovery limits](../plugin-database-isolation.md#approved-upgrade-from-0125).

## Verification

Isolated SQLite and PostgreSQL 17/18 checks cover shared physical storage/pooling, identical logical table names, concurrent schema scopes, restart, callbacks executed once, rollback, generation fencing, missing stores and retryable uninstall. The actual released `smartdoca/doca:0.1.25` image creates synthetic retained core rows, private business records, credentials and objects. Verification checks rejection preserves old rows/declarations, normal old-host uninstall clears private data, and reinstall against the same core starts with an empty shared business store. See [verification evidence](../verification/shared-plugin-database-2026-10-15/README.md).

The deep knowledge-book sample remains at the user-requested stopping point described in [0.1.25](0.1.25.md#known-validation-limit); this patch does not resume or claim completion of that separate acceptance.
