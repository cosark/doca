# Doca 0.2.10 — Image tasks and native schema alignment

[简体中文](0.2.10.zh-CN.md)

MCP image generation previously looked up a derived operation namespace as though it were the original user job, returning 404 before contacting the image provider. Scope validation now reads the actual owned original job. Existing operation IDs, request claims, at-most-once behavior, usage records and document formats remain unchanged.

Direct Volcengine Agent Plan image generation was verified through Doca's existing Seedream adapter using `https://ark.cn-beijing.volces.com/api/plan/v3`, model `doubao-seedream-5.0-pro` and explicit profile `doubao-seedream-5-0-pro-260628`. One isolated request returned HTTP200 after 63.354 seconds and saved a 2731×1536 UI bitmap and its original candidate. A separate process reopened the database and reused the saved receipt and image bytes with zero provider calls and unchanged call/operation/asset rows. This supports bypassing the earlier intermediary's 60-second cutoff; the precise live gateway directive remains unverified.

The earlier HTTP504 request is separate: no returned image, unknown usage, retained original call/operation and no automatic retry or reconciliation. No production provider configuration is changed, and no API key is included in code or release artifacts. The supplied key was used only for request authentication in memory.

Type checks, production builds and the focused MCP/retry/scope checks passed. Two complete suite runs each passed 3334 tests and timed out on different existing download/image fixtures; both fixtures passed independently. No single all-green full-suite run is claimed. Native amd64/arm64 release gates and public release receipts are recorded after acceptance.

PostgreSQL image-candidate saving is fixed by widening assets.purpose from varchar(16) to varchar(32). Startup now supports approved native column alignment: PostgreSQL varchar widening/defaults/nullability, and SQLite nullability only. Existing NULL values block tightening; old rows are never filled or rewritten for default changes. SQLite default changes, type conversion/shrinking, field removal and key/check changes still stop the entire transaction. There is no table rebuild, system-schema edit or automatic downgrade. Released 0.2.9 source-created SQLite/PG17/18 fixtures retain all 131 table hashes; PostgreSQL changes only the purpose width. Read the [upgrade contract](../database-schema-evolution.md) and back up before updating all hosts together.

Shutdown also waits for an in-flight queue claim before draining active jobs, preventing late access to an already closed database. Existing task states, receipts and retry rules remain unchanged. No SDK, browser preference or queue-format change is introduced. Keep the [0.2.8 upgrade/recovery requirements](0.2.8.md), retain all data and the deployment credential master key. See [direct-image and recovery evidence](../verification/ui-image-ark-plan-2026-10-23.md) and [Web image-layer measurements](../verification/image-web-layers-2026-10-23.md).
