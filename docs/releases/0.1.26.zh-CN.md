# Doca 0.1.26

[English](0.1.26.md)

所有插件改为共用一个业务数据库，与核心库分开。添加插件时自动创建命名空间及声明的表，管理员不再逐个创建数据库和账号。

## 配置

SQLite 自动使用 `<DOCA_SQLITE_PATH>.plugins.db`，可用 `DOCA_PLUGIN_DATABASE_PATH` 覆盖。PostgreSQL 只需通过 `DOCA_PLUGIN_DATABASE_URL` 配置一次共享业务库和受限角色。每实例所有插件共用一个连接池，`DOCA_PLUGIN_DATABASE_POOL_MAX` 限制总连接数（默认 4，范围 1–20）。PostgreSQL 按插件隔离 schema，SQLite 给物理表添加前缀。公开 SDK 接口和 SDK 表名不变，无需发布 npm 包。

卸载只删除目标插件声明的表及私有数据，保留其他插件和共享库。库／命名空间／表丢失、标记不符或结构异常时明确拒绝，不会静默重建业务数据。详见[存储约定](../plugin-database-isolation.zh-CN.md)。

## 从 0.1.25 升级的必要步骤

**必须先在 0.1.25 正常卸载全部外部业务插件，再停止宿主及更新。** 已确认方案会丢弃插件私有业务记录、加密凭证和私有对象，不迁移。重装后重新配置并绑定账号。核心用户、文档、权限、普通用户文件和原凭证主密钥保留。

先备份核心库、旧插件库／文件、私有文件存储和配置。旧版卸载／清理失败须先在旧版解决。停止全部实例，移除 `DOCA_PLUGIN_DATABASES_JSON`／`DOCA_PLUGIN_DATABASE_DIR`，配置共享库，部署、重装并重启全部实例。有效格式 2 安装及旧配置会被明确拒绝，新声明使用宿主格式 3。不提供旧库读取、自动迁移或自动删除旧库。核心 DDL 和 `schema_baseline.id` 不变，更早结构／历史／知识册升级门禁仍适用。

新写入前可用匹配的原始备份和旧部署恢复。新写入后须保留新数据库／文件并另行确认恢复决策，直接恢复旧备份会丢失后续数据。旧宿主不能读取格式 3，不支持新旧混跑。详见[具体步骤和恢复边界](../plugin-database-isolation.zh-CN.md#从-0125-升级的已确认方案)。

## 验证

隔离 SQLite 和 PostgreSQL 17/18 检查覆盖共享物理存储／连接池、相同逻辑表名、并发 schema 作用域、重启、回调仅执行一次、回滚、代次封禁、库丢失及可重试卸载。实际发布的 `smartdoca/doca:0.1.25` 镜像创建合成核心行、插件私有业务记录、凭证和对象；验证拒绝时旧行／声明不变，旧版正常卸载清掉私有数据，再在同一核心库重装到空共享业务库。见[验证记录](../verification/shared-plugin-database-2026-10-15/README.md)。

深度知识册样册维持 [0.1.25](0.1.25.zh-CN.md#已知验证限制) 所述用户指定停止状态；本补丁不恢复该任务，也不宣称完成其独立内容验收。
