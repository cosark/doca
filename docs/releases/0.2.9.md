# Doca 0.2.9 — Smaller Web updates

[简体中文](0.2.9.zh-CN.md)

This packaging release separates the Web build into reusable image layers. CAD resources, fonts, the HTML entry and 16 code groups have their own `COPY --link` layers. A Vite chunk's changing content hash does not move its stable name into another group. Files, URLs, permissions and rendering features are preserved.

An isolated OCI experiment with the actual 483-file Web build updates and renames one entry JS chunk and rewrites its HTML reference. It reuses 17 of 19 Web layers; new layers total 334,554 compressed bytes, compared with roughly 19.7 MB for the preceding whole-Web layer. This demonstrates that boundary, not a fixed download promise for every update. Actual transfer depends on changed chunks, dependencies/base images and locally retained layers. Layer headers add a small amount to the complete image.

The five editor npm versions, browser preferences, server APIs, document codecs, database structure and browser queue records are unchanged from [0.2.8](0.2.8.md). Continue following its upgrade and recovery requirements, preserving all data and stopping older senders as directed. No migration, compatibility reader, renderer download or browser-sandbox change is introduced.

Verification compares every original Web file and directory, checks production Dockerfile coverage and validates every OCI blob hash. Native amd64/arm64 release gates check the resulting image's complete runtime/Web files, authentication, original image bytes, sandboxed PDF, Canvas pixels and Office conversion before publishing version/latest. Publication receipts and actual incremental layer totals are recorded after those gates pass. Production deployment remains separate.

The earlier UI-image HTTP504 still has no returned image and unknown usage; records remain retained and automatic paid retry stays blocked. The required Mastra memory patch remains unchanged.
