# Doca 0.1.30 — PostgreSQL 插件数据库账号配置

[English](0.1.30.md)

插件业务库登录账号交由部署者选择。启动接受超级用户、具有 `CREATEDB`／`CREATEROLE`／`BYPASSRLS` 属性的账号、角色成员关系，以及拥有核心表权限的账号；核心库和插件库也可使用同一个账号。不新增开关，不自动修改账号权限。

插件业务库仍须与核心库分离。数据库和 schema 操作仍需实际的 PostgreSQL 权限；缺少配置或授权时，返回具体宿主诊断，取代通用插件存储错误。[配置规范](../plugin-database-isolation.zh-CN.md)包含可选的专用账号配置示例。

## 升级与回退

项目所有者于 2026-10-16 明确同意此次账号准入规则调整。已有格式 3 声明、标记、安装代次、schema 定义和数据版本均保持原样，不涉及数据库 DDL、数据迁移、历史默认值或权限改写。既有格式 2 拒绝和先卸载再升级约定不变。

部署时保留现有数据库、文件、凭据和配置。回退至 0.1.26–0.1.29 会恢复旧账号拒绝规则，新版本接受的管理员账号可能使旧宿主无法启动。回退所用账号配置须符合旧宿主规则，并保持已有业务数据可访问；宿主不重置数据或自动更改所有权／授权。

## 验证

隔离 PostgreSQL 17/18 回归覆盖管理员属性、角色成员关系、核心表授权、核心库目标拒绝、同一管理员账号连接不同数据库、重启后记录保留、普通账号缺少授权时的失败及重试。SQLite 行为保持不变，见[验证记录](../verification/plugin-postgres-permissions-2026-10-16.md)。
