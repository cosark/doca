# Doca 0.1.21

[English](0.1.21.md)

共享文件夹链接新增人数限制，文件夹邀请补齐通知和资源工单。同一兼容代际内，已审定的数据库增量结构会在启动时自动补齐。插件 SDK 保持 0.1.10。

## 改动

- 文件夹链接支持预设人数、自定义正整数和不限人数。新链接默认 1 人；重复访问、已有足够权限的用户不重复占名额。并发加入在事务中校验上限。
- 邀请遵循已有的直接授权或受邀确认策略。直接授权生成已完成工单和权限变更通知；需要确认时生成待处理工单及邀请通知，接受后才授权。工单支持文件夹筛选、资源跳转、拒绝、撤销和提醒，操作校验当前权限。
- 新库创建与结构比较共用最新 DDL。已审定的新增表、字段及普通索引在一个事务中自动补齐。默认值、类型、约束、唯一索引变化，以及删除或未知表，会在持久化修改前报告确认计划。
- 只记录最新已安装结构，已存在字段丢失时不能伪装成新增字段并重置安全设置。宿主管理的插件私有表不参与核心结构整理。多个宿主同时升级会串行处理，PostgreSQL 获得结构锁后读取最新目录。

## 升级与恢复

兼容代际保持 `doca-2026-10-09-history-storage-v1`。结构符合支持范围的 0.1.20 数据库会在启动时完成增量升级。已有文件夹令牌、角色、时间和成员权限保持原值；旧链接明确补为不限人数、不过期；新的邀请与链接加入记录表从空表开始，不补造历史事实。

部署前备份数据库、文件存储和配置，保留 Compose 项目名与 `DOCA_CREDENTIAL_MASTER_KEY`。启用新限制前先更新全部宿主实例，旧宿主不会执行新的人数限制或确认流程。更早兼容代际仍遵守原有显式历史升级和中断回退检查。见[数据库结构演进](../database-schema-evolution.md)与[部署说明](../deployment.zh-CN.md)。

结构升级失败时事务整体回滚。写入新记录后如需降级，应另行确认数据保留和恢复方案；恢复升级前备份会丢失后续写入。不要删除或重置已有数据库来绕过待确认差异。

## 验证与交付

验证覆盖 SQLite、PostgreSQL 旧结构升级、原值保留、重复与并发启动、权限和邀请流程、并发人数限制、类型检查、生产构建、文档链接及默认全量测试。发行验证附件同时记录实际 0.1.20 镜像升级和双架构启动结果。

- GitHub 标签 `v0.1.21`，附 Web 资源、仅使用镜像的部署包及校验文件。
- Docker `docker.io/smartdoca/doca:0.1.21` 与 `latest`，支持 Linux amd64、arm64。
- SDK 导出、插件数据版本与编辑器协议未变更。

额外的 PostgreSQL 历史保留并发测试仍会出现归档主键冲突，原代码也可复现。这项已有问题单独记录；文件夹名额并发与结构升级测试通过。
