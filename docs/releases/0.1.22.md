# Doca 0.1.22

[简体中文](0.1.22.zh-CN.md)

Fix PostgreSQL 18 startup upgrades from the 0.1.20 folder schema. Release 0.1.21 incorrectly treated the new `NOT NULL` entries for `revision` and `structure_json` as table-constraint changes and stopped before applying the upgrade.

PostgreSQL column nullability remains checked through column metadata. Its duplicate `pg_constraint` entries are excluded from table-constraint comparison. Existing nullability changes still require review. The approved field defaults, retained data, transactional rollback and compatibility generation are unchanged; no manual SQL or database reset is required.

Verification covers PostgreSQL 17 and 18, additive old-schema upgrades, concurrent/repeated startup, rejection of existing nullability changes, folder permissions and invitations. An actual released 0.1.20 image creates an isolated PostgreSQL 18 database, which the new image upgrades while retaining user, folder, member, document and link records. SQLite regressions, the full default suite, type checking, documentation and both image architectures are also checked.

Use `docker.io/smartdoca/doca:0.1.22` or `latest` (Linux amd64/arm64). Back up the database, file storage and configuration, preserve the existing credential key and Compose project, and update every host instance before enabling new sharing restrictions. Startup retries the previously rolled-back additive upgrade. See [database structure evolution](../database-schema-evolution.md) and [deployment](../deployment.md).

The plugin SDK remains 0.1.10. GitHub tag `v0.1.22` includes Web assets, deployment files, checksums and release verification.
