# Doca 0.1.21

[简体中文](0.1.21.zh-CN.md)

Shared-folder links now support member limits. Folder invitations deliver notifications and resource tickets. Reviewed additive database upgrades run automatically within the current compatibility generation. The plugin SDK remains 0.1.10.

## Changes

- Set a preset, custom positive member limit, or unlimited access on folder links. New links start at one member; repeated visits and users with sufficient existing permissions do not consume another place. Admission is checked transactionally under concurrent requests.
- Match the existing direct/invitation distribution policy. Direct grants create completed tickets and permission notifications. Consent invitations create pending tickets and notifications, then grant access after acceptance. Tickets support folder filters, resource links, rejection, cancellation and reminders with live permission checks.
- Reuse the latest DDL for fresh creation and structural comparison. Automatically apply reviewed new tables/columns and safe ordinary indexes in one transaction. Changed defaults, types, constraints, unique indexes, removals and unknown tables produce a review plan before any persistent change.
- Record only the latest installed footprint, so missing previously installed fields cannot be treated as new fields and silently reset security settings. Keep host-managed plugin tables outside core reconciliation. Serialize simultaneous host upgrades, including fresh PostgreSQL catalog reads after acquiring the schema lock.

## Upgrade and recovery

The compatibility generation stays `doca-2026-10-09-history-storage-v1`. A 0.1.20 database with the supported structure receives the additive upgrade at startup. Existing folder tokens, roles, timestamps and memberships remain unchanged. Old links become explicitly unlimited with no expiration; new invitation/admission tables start empty. Historical invitation or admission facts are not fabricated.

Back up databases, file stores and configuration, preserving the Compose project name and `DOCA_CREDENTIAL_MASTER_KEY`. Update all host instances before enabling new restrictions; old hosts do not enforce the new limit or consent flow. The existing explicit history upgrade and interrupted-rollback gates remain in effect for preceding generations. See [database structure evolution](../database-schema-evolution.md) and [deployment](../deployment.md).

An unsuccessful structural upgrade rolls back its transaction. Downgrading after new records have been written requires a separately reviewed preservation/recovery plan; restoring a pre-upgrade backup loses subsequent writes. Do not delete or reset an existing database to bypass a review-required difference.
