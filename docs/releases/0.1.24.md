# Doca 0.1.24

[简体中文](0.1.24.zh-CN.md)

0.1.24 aligns released 0.1.22 databases with the current structure during startup, without requiring the knowledge-book maintenance command. It uses the latest DDL and existing schema reconciler, applying reviewed additions, rechecking structure and recording the footprint/target generation in one schema-lock transaction.

The final approved policy leaves every business row untouched, including old SQL-generated book outcomes, runs, human tasks and publication pointers. No separate cleanup, automatic body conversion or legacy runtime reader is added. New outcomes use native object storage. Residual old records may require manual handling before their book is usable. Existing 0.1.23 objects, references and outcomes remain intact.

## Upgrading existing deployments

Stop all old hosts, back up SQL, private storage and configuration, and retain the credential master key, store IDs and deployment identity. Update to this release and start it. Update every host and web build together.

```sh
docker compose stop
docker compose pull
docker compose up -d
```

Automatic alignment supports the exact preceding generation `doca-2026-10-09-history-storage-v1` and records target `doca-2026-10-12-book-payload-storage-v1`. Earlier generations still need their approved history-storage upgrade. Unknown/interrupted generations and review-required differences stop without partial changes. The generation records the target structure; it does not mean leftover JSON has been converted into readable outcomes. No automatic VACUUM or deletion of unknown business tables occurs.

The existing optional lossless book maintenance remains available before the first 0.1.24 startup if old outcomes must remain usable in the native format. Once schema alignment changes the generation, the conversion's source generation no longer applies. See [operations and recovery](../knowledge-book-storage-verification.md). Preserve all data and later writes during rollback; old hosts cannot directly use the target generation.

## Publication and verification

This retains the Slate 0.4.14 and Canvas 0.4.3 integrations from 0.1.23 and the already published plugin SDK 0.1.11. SDK contents are unchanged and need no duplicate npm release. The private host package is distributed through GitHub and Docker Hub.

GitHub `v0.1.24` includes web assets, deployment files, checksums and release verification. Docker `smartdoca/doca:0.1.24` and `latest` support Linux amd64 and arm64. Verification records cover SQLite/PostgreSQL 17/18 schema alignment, every-row retention, transaction rollback, repeated/concurrent startup, native object reads, actual released 0.1.22 fixtures and both container architectures. All evidence uses synthetic data; no production database or user document was modified.
