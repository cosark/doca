# Doca 0.1.25

[简体中文](0.1.25.zh-CN.md)

This release combines long-book execution, current-book assistant context, management controls and notification counts with editor upgrades, AI file delivery and independent plugin databases. The release includes the fixes at the user-requested stopping point; the deep knowledge-book sample has not completed acceptance.

## Knowledge books

Long writing establishes coherent chapters, assigns claims to chapter sections and batches writing, organization and inspection by whole paragraphs. Character budgets are allocated per chapter and later nodes preserve chapter identity. Chapter depth checks inspect causal derivations, complete worked cases, diagnostic evidence and applicability boundaries. Detailed inspection checks whole paragraphs, literal quantity clauses and related normative blocks; failed local assessments can receive one independent reinspection with different supporting blocks regardless of rejection wording. Intermediate aggregation consolidates the present chapter observations and defers whole-book coverage to final acceptance. Complete negative diagnostics guide repairs only when candidate and source-scope hashes match. A four-hour execution deadline retains per-request protections, worker leases and cancellation. Structurally valid but incomplete batches receive a complete repair before further subdivision.

Configuration, workflow and artifacts retain version 1. All existing data remains without migration or conversion. Resume reuses completed nodes under existing revalidation rules and executes failed nodes with bounded processing. Earlier code can read the same artifacts after rollback, but its large-text execution limits may recur. Actual generation and diagram verification use isolated fixtures.

Book assistant conversations prioritize the current book. Tool guidance and node parameters are clearer. Cards expose rename and trash actions, clicking outside closes the pipeline node drawer, and notification icons display the actual unread count.

## Editors and AI

Slate 0.4.15 and Sheet 0.2.2 are pinned with the existing DOCX patch. Native rotation and image selection/preview use current host integration; spreadsheets use the package's select-all control and the 0.2.2 hyperlink cancellation/unlink fix. Approved 18/72 defaults apply to appended and virtual recovery worksheets without rewriting existing baseline fields or original Yjs bytes. Exact protocols, schemas 3/6, epochs, ACKs and comment ownership remain. See the [editor upgrade verification and rollback limits](pending-editor-package-upgrade.md).

Mention menus handle native editor keyboard selection and Enter while directory results load; stable spreadsheet draft subscriptions avoid update loops. Collaboration cursors retain the caret for empty nicknames, and comment/visibility controls share consistent sizing. Three isolated browser rounds each passed 29 checks and a 60-second idle observation; see the [interaction verification record](../verification/editor-interactions-2026-10-15/README.md).

AI file delivery uses the existing receipt shape for idempotent writes. Document-generation requests default to online rich text; explicit file requests produce files. Images use compressed thumbnails and permission-checked caching; non-image AI attachments retain private, non-cacheable responses.

## Upgrading existing deployments

**Deployments with external business plugins must normally uninstall all of them on the old host first.** The approved policy discards old private plugin records, encrypted credentials and private objects without migration. Reinstall and reconfigure/rebind accounts afterwards. The new host rejects residual old installations or business tables without automatically deleting them. Core users, documents, permissions, ordinary files and the credential master key remain. See [independent plugin databases](../plugin-database-isolation.md) for exact steps, PostgreSQL per-plugin databases/restricted roles and recovery limits.

Back up databases, file storage and configuration, retaining the original key and deployment identity. After old-host plugin uninstall, stop all hosts, update every server and Web build, then reinstall plugins and restart. Mixed old/new host operation is unsupported.

The core target generation remains `doca-2026-10-12-book-payload-storage-v1`. Existing approved reconciliation, history upgrade and book-maintenance limits follow [0.1.24 requirements](0.1.24.md). This release changes neither book persistence formats nor editor data conversion. Older hosts cannot read the new plugin database layout. Retain later writes when considering recovery after new-host operation.

The candidate, private test database and diagnostic records are retained locally. This release does not claim complete factual/depth acceptance and does not restart that generation.
