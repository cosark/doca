# Doca 0.2.5 — MCP services and editor integration

[简体中文](0.2.5.zh-CN.md)

External AI clients can use Doca assistant tools and SKILLs through Streamable HTTP. Personal settings provides a master Switch and separate services/tokens with all or selected grants. Company services require a target `userId` on every operation and use that user's current permissions. Each service includes connection examples and a copyable one-sentence AI installation instruction. Native reports, canvas, presentations, spreadsheets, folders and chunked file transfers use the existing host services. See [MCP setup and lifetime limits](../mcp.md).

Canvas 0.5.6 and Sheet 0.2.4 are integrated. Historical/trash canvas previews use authorized download callbacks for image copying. The approved Canvas behavior recognizes historical diagram wrappers and applies the current geometry and ellipse/diamond endpoint rendering; opening, selection and viewport changes preserve original model/checkpoint bytes, while explicit editing uses normal collaborative transactions and undo. There is no batch conversion, field backfill or schema change. Canvas schema 1 and Sheet schema 6 remain exact requirements. Existing historical readers and recovery paths are unchanged. See [package audit and browser acceptance](../verification/editor-packages-2026-10-20/README.md).

AI canvas viewing and independent inspection use the configured vision model when needed. Automatic routing, label placement and diagram resizing are checked against native rendering. Collapsing the assistant sidebar preserves its images and messages. Search results navigate and dismiss search reliably, including when the target is already open; browser tabs use the document format icon when no custom icon exists. The [canvas acceptance record](../verification/ai-canvas-tools-2026-10-19/README.md) includes configured-provider testing and native route verification.

## Upgrade and recovery

Back up the database, object store, deployment configuration and credential master key before upgrading; update server and Web together. Four new empty MCP tables are added through current DDL and `schemaEvolution`, without changing `doca-2026-10-12-book-payload-storage-v1`. Existing content, ACLs and configuration are retained. Personal MCP remains disabled until explicitly enabled. The unused old MCP runtime and `/ai/mcp-keys` API are retired as approved; old credentials are rejected without conversion. The inert `ai_mcp_keys` table and rows remain solely for preservation, with no runtime reads.

The [MCP acceptance record](../verification/mcp-2026-10-20/README.md) upgrades actual released 0.2.4 data on SQLite and PostgreSQL 17/18, verifies 120 original table hashes, repeated/concurrent startup and rejection without partial writes. Keep previous package artifacts and lockfiles for a reviewed application recovery; preserve later writes and new MCP records before rollback. Older binaries cannot enforce the new service grants and do not promise identical rendering of newer interactions. No automatic downgrade or data deletion is provided. Earlier [0.2.2 upgrade requirements](0.2.2.md#upgrade-and-recovery) still apply to older installations.

MCP contexts and visual inspection state belong to one server instance. Route a live context consistently; after restart or expiration, open a new context and inspect saved artifacts. Token/grant changes invalidate live contexts. Optional paid external providers retain their existing configuration and policies; the MCP demo does not claim to have exercised every provider or every editor gesture.

Release verification is recorded [here](../verification/release-0.2.5/README.md). Images are `smartdoca/doca:0.2.5` and `latest` for Linux amd64 and arm64. The GitHub Release includes matching Web assets and the image-only deployment bundle. Publishing artifacts does not upgrade a running site automatically.
