# Doca 0.1.20

[简体中文](0.1.20.zh-CN.md)

This release fixes search synchronization lifecycle and task tracking, and makes plugin branding consistent across host navigation and administration. The plugin SDK stays at 0.1.10.

## Changes

- Start search synchronization after core plugins finish registering their sources. Stop in-flight search work before releasing those sources during application shutdown, preventing `Search source is not registered` failures.
- Keep tracking an accepted Meilisearch task while it is queued or processing. A five-minute local deadline no longer abandons a task that Meilisearch is still preparing; application shutdown still ends the wait.
- Show diagnostics from the current embedding task and its own batch, rather than attributing unrelated historical quota errors to a new task.
- Use store PNG icons for plugin navigation, including the sidebar, top-right actions, More menus and administrator entries. Explicit navigation icon overrides remain effective.
- Share plugin icon rendering across store cards, installed and upgrade lists, plugin details, navigation settings and extension buttons. Managed store/npm installations can resolve branding while pending startup or disabled; local packages and unknown plugin IDs do not trigger store lookups.

## Verification and distribution

The release verification attachment records full-suite checks, documentation validation, image startup/shutdown probes, asset checksums and the published image digest.

- GitHub tag `v0.1.20`, with Web assets, the image-only deployment bundle and SHA-256 checksums.
- Docker `docker.io/smartdoca/doca:0.1.20` and `latest`, for Linux amd64 and arm64.
- SDK exports, plugin manifests, store protocol and installation records keep their existing formats.

## Deployment and rollback

The database baseline stays `doca-2026-10-09-history-storage-v1`. No database migration, persisted-data conversion or old-format adapter is added. Existing strict baseline validation and explicit history maintenance commands are unchanged.

When updating a 0.1.19 deployment, preserve databases, files, configuration, the Compose project name and `DOCA_CREDENTIAL_MASTER_KEY`. Rebuild an affected search index after updating and confirm that its Meilisearch task succeeds; model availability alone does not establish task completion. Earlier baselines follow the [0.1.15 requirements](0.1.15.md). Previous images and release artifacts remain available for rollback after stopping writes and backing up data.

See [deploy without GitHub access](../deployment-without-github.md) for online and offline image delivery. External model and store services must remain reachable from the deployment.
