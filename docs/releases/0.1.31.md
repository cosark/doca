# Doca 0.1.31 — Canvas, presentations and AI authoring

[简体中文](0.1.31.zh-CN.md)

Doca now uses the published `@smartdoca/canvas` 0.5.2, `@smartdoca/slate` 0.4.22 and `@smartdoca/slides` 0.3.0-alpha.3. Canvas fixes consecutive Chinese IME input, keeps element toolbars attached while panning/zooming, and grows table rows to fit wrapped text and media. The temporary Canvas 0.5.0 artifact is removed from the runtime dependency path.

Canvas resources use host-owned upload, progress/cancellation and authorized preview callbacks. Relative text selections and scene pointers use the existing authenticated presence channel. Presentation text insets and native tables use the current controller.

The AI assistant can create and edit complete presentations, flowcharts, mind maps, native canvas tables, phone/tablet UI designs and editable vector patterns. Tools and built-in skills describe current commands and exact units, protect table structure, delete logical mind-map descendants, and report final table coordinates. Obsolete canvas/PPT argument aliases, element guessing and pixel/EMU heuristics are removed. Independent delivery review now consumes streamed responses while retaining read-only snapshot checks.

Workspace improvements include document-source filtering and upload entry, more reliable native-selection references in the AI composer, protection against stale chat snapshots, and live administrator online-state reconciliation. Spreadsheet color-only AI updates preserve existing values and formulas.

## Upgrade and recovery

Update server and Web together. Preserve databases, assets, configuration, the credential master key, original checkpoints and pending updates. Core database DDL and compatibility generation are unchanged. Canvas remains `aidcanvas-yjs` schema 1; no document conversion, field backfill, epoch rewrite or automatic migration is introduced. The Canvas 0.5.2 model runtime and public API match the tested 0.5.0 artifact; its runtime fixes live in the editor.

**Presentations are new-documents-only for this revision.** The owner explicitly approved revision 6 (`eppt-yjs-v6`, document schema 2, protocol 1). Existing revision-5 documents and old clients are rejected. Their checkpoints, update logs, epochs, history and pending message identities remain intact; this release does not convert them. Keep the previous deployment and dependency pins for recovery. Earlier editors are not guaranteed to read later writes; preserve new data before rollback.

The already released 0.1.30 PostgreSQL plugin-account policy remains unchanged. Plugin/core databases must remain separate. No SDK publication or plugin-data reset is part of this release.
