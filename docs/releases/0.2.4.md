# Doca 0.2.4 — Knowledge-book presentation and batch recovery

[简体中文](0.2.4.zh-CN.md)

The book reader has a compact expandable directory with visible tree connectors, folder/file icons and clearer selected states. Book cards use a quieter hierarchy and readable wrapping titles. Workflow nodes, edges and status markers share consistent styling, with an accessible compact overview and a scroll hint for the mobile palette. Article diagrams use a bounded reading surface.

Complete validated model requests now survive an interrupted node, reducing repeated extraction, planning, writing and quality-review requests when the original frozen run resumes. Negative verdicts, source authorization and required publication checks remain enforced. Partial streams are discarded.

This approved addition creates an empty `knowledge_book_batch_checkpoints` table through current DDL and `schemaEvolution`, without changing the database generation or historical node/run/release formats. No historical data is converted or backfilled. Independent private v1 checkpoint references reuse immutable object storage, upload journaling and garbage collection. Unknown versions, corrupt results, missing objects or changed model/algorithm settings in the same scope stop recovery explicitly.

Back up the database and object store, stop workers and upgrade all executors and garbage collectors together. Mixed old/new instances are unsupported. `DOCA_BOOK_BATCH_CHECKPOINTS=off` on the current binary disables batch recovery while preserving rows and object pins; it requires restart. Existing checkpoints prevent offline body-storage rollback until a separately approved preservation plan exists. Permanent book deletion follows the existing explicit deletion flow.

The checkpoint verification includes SQLite 211 tests, PostgreSQL 17.11 and 18.6 each 98 tests, TypeScript, actual released 0.2.3 data upgrade and real SIGKILL/cold-process recovery. See the [contract](../knowledge-book-generation-performance.md), [checkpoint verification](../verification/knowledge-book-checkpoints-2026-10-19/README.md) and [release verification](../verification/release-0.2.4/README.md). These results do not measure the reported production run's duration.

Images are `smartdoca/doca:0.2.4` and `latest`, supporting Linux amd64 and arm64. The GitHub Release includes matching Web assets and the image-only deployment bundle. Earlier [0.2.2 upgrade requirements](0.2.2.md#upgrade-and-recovery) still apply when upgrading from older installations. Publishing these artifacts does not update a running site automatically.
