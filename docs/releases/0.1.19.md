# Doca 0.1.19

[简体中文](0.1.19.zh-CN.md)

This release fixes Meilisearch index rebuilding and adds a deployment handoff for business servers without GitHub access. The plugin SDK remains at the published 0.1.10 release.

## Changes

- Transient embedding request errors no longer determine an indexing task's final status. Wait for the accepted task to finish instead of resubmitting work still in progress; preserve redacted diagnostics on timeout.
- Rebuild existing active indexes in a separate version and swap only after every task succeeds. A failed first rebuild preserves the active index and its query results.
- Show rebuild failures separately from automatic synchronization failures in search administration, listing each failed source and reason while redacting Bearer and API keys.
- Add bilingual deployment instructions with copyable Compose and `.env`, initialization and administrator password recovery, Docker Hub pulling, and offline image delivery.
- `node scripts/pack-deployment.mjs` / `pnpm deploy:pack` generates an image-only deployment bundle and SHA-256 checksum with the environment example, Chromium seccomp policy, and administrator scripts. It includes no workspace secrets or user data. Official Releases attach the bundle automatically. Administrator initialization and password recovery explicitly use the local image without a registry pull.

## Verification and publication

Frozen dependency installation, TypeScript, the Web build, and 57 bilingual documentation pages passed. The full suite passed all 268 files: 2,654 tests passed and 3 environment tests were skipped. The release verification attachment records SDK artifact comparison and final image checks. Deployment checks use isolated databases, volumes, and test accounts.

- GitHub tag `v0.1.19`, with Web assets, deployment files, checksums, and verification records.
- Docker `docker.io/smartdoca/doca:0.1.19` and `latest`, Linux amd64 and arm64.
- JavaScript, declarations, and exports in `@smartdoca/plugin-sdk@0.1.10` match its npm artifact; the search and deployment changes require no new SDK interface. Its `web-plugin-registry@0.1.3` dependency has an earlier unpublished built-in navigation difference, recorded in the verification attachment.

## Deployment and rollback

The database baseline remains `doca-2026-10-09-history-storage-v1`. This release adds no old-format adapter, database migration, or user-data conversion. Existing strict baseline validation and explicit history upgrade commands are unchanged.

When replacing a 0.1.18 image, preserve databases, files, configuration, the Compose project name, and `DOCA_CREDENTIAL_MASTER_KEY`. Earlier baselines follow the [0.1.15 upgrade requirements](0.1.15.md). Stop writes and back up data before rollback; previous artifacts and tags remain available. See [deploy without GitHub access](../deployment-without-github.md) for offline delivery.

Application health does not replace renderer acceptance on the target host. External AI, identity, plugins, and cloud storage still require network access; those services are not part of this deployment.
