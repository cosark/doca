# Doca 0.2.12 — Browser assistant navigation recovery

[简体中文](0.2.12.zh-CN.md)

The browser assistant could fail with `clipper_page_unsupported` after navigating to another page because its capture receiver was not yet available. It now loads its bundled capture scripts into the current HTTP(S) page's top frame and retries capture once. An existing receiver is reused, capture errors are preserved, and duplicate script injection does not register another toolbar or message listener.

The extension is version 0.2.1 and declares the `scripting` permission for this recovery, using its existing HTTP(S) site access. Update Doca, download the updated extension from Browser assistant settings, replace the unpacked extension files and reload the extension in Chrome / Edge. Existing installed extensions do not receive this fix just by updating the server.

Verification covers an unavailable receiver during real Chromium MV3 navigation, capture before `document_idle`, subsequent in-page navigation and another tab. The synthetic transport sends three messages to the same conversation with no duplicate submissions or page reloads. No paid model calls or user documents are used. See the [release verification](../verification/release-0.2.12.md).

This patch adds no database structure, persisted-format conversion, SDK adapter or data migration. Keep the existing [0.2.8 upgrade/recovery requirements](0.2.8.md) and [database contract](../database-schema-evolution.md), and preserve databases, files, configuration and the credential master key when replacing the deployment. Publication supplies GitHub assets and Docker Hub images; it does not deploy the production site.
