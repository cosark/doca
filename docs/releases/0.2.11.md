# Doca 0.2.11 — Editor fixes and browser assistant

[简体中文](0.2.11.zh-CN.md)

Doca now pins the official npm releases `@smartdoca/canvas` 0.5.15 and `@smartdoca/sheet` 0.2.12. Newly drawn native tables participate in fully enclosing marquee selections before reload. Spreadsheet filters persist the approved range expansion when criteria are confirmed or contiguous records are appended; content and automatic expansion share one collaborative undo step. Opening, cancellation, clearing criteria, styles and content outside the filter columns do not expand stored ranges.

Canvas, spreadsheet and slides comment annotations follow the comment sidebar and are hidden initially. The separate eye button is removed. Canvas note mentions retain their host locale context when reopening user cards. Comment sending feedback stays visible until the committed comment appears in the refreshed list. Renaming rich-text and Markdown titles preserves their existing formatting where applicable.

The browser assistant recaptures the current tab for each new message, preserves frozen retry material and can read page text when an image is unavailable. Full-page capture still refuses missing images rather than committing incomplete content. Selection tools refresh authentication state and guide users to sign in, retry or refresh an outdated content script. The extension quick-note UI is removed; existing documents and the server API remain intact. Update the extension and refresh existing tabs after upgrading.

Public editor APIs, schema 1/6, baselines, epochs, checkpoints and pending document updates retain their current formats. Existing historical readers, worksheet defaults, browser authentication and AI pending-queue rules remain unchanged. No new format adapter, migration, field backfill or database structure change is introduced relative to 0.2.10. Preserve later content and the preceding deployment, package pins and lockfile for rollback; earlier Sheet packages read saved native ranges but do not author subsequent implicit extensions.

Follow the existing [0.2.8 upgrade/recovery requirements](0.2.8.md) and [database contract](../database-schema-evolution.md), preserve database/file volumes and the credential master key, and update server, Web and extension together. Verification uses isolated accounts, documents and databases. Publication does not deploy the production site. Evidence: [editor comments](../verification/editor-comments-2026-10-23.md), [filter range](../verification/sheet-filter-range-2026-10-23.md) and [browser assistant](../verification/browser-assistant-fixes-2026-10-23.md).
