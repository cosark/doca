# Doca 0.1.32 — Editor upgrades, access status and title icons

[简体中文](0.1.32.zh-CN.md)

Rich text inside canvas notes, cards and table cells supports @user suggestions and pasted same-origin Doca document links as native atomic inline elements. The host supplies authorized directory lookup, user cards and document titles; accepted mentions and references enter the existing durable collaboration commit, notification and reference-index paths. Copy/paste, deletion, undo/redo, peer synchronization and reload preserve stable reference UUIDs.

Canvas attachment previews now use `onAttachmentPreview` in active and readonly/history/trash/audit surfaces, through the shared permission-checked file viewer. Images retain the resource callback; downloads retain host authorization.

Slate upgrades to the published 0.4.23, including its LeaferJS mind-map workspace and preview. The original DOCX style patch is unchanged. Canvas includes 0.5.3's preview/navigation fixes and the new 0.5.4 native inline extension API, published to npm as `@smartdoca/canvas` 0.5.4. The host installs the exact registry version and integrity; no local archive is used.

Document access status is derived from effective permissions: red Private for owner-only access, blue Collaborative for multiple people, and green Public for access open to authenticated users or everyone. Disabled users are excluded; inherited permissions, library management rights and explicit blocks are respected. Solid tags with white text follow titles on the home page and in the top-left document header. Document lists have a separate Access column. Rich-text body headings retain their original rendering. Narrow document headers wrap to keep the title and status visible.

An emoji followed by a space at the start of a title replaces the type icon in lists, navigation trees, pinned items and search results, without repeating the prefix in the displayed title. Creation and renaming offer common icons, manual emoji entry/paste and removal. Titles remain native strings; existing titles are not backfilled or rewritten. Failed saves retain the draft for retry.

## Upgrade and recovery

Update server and Web together. The owner approved adopting the new mind-map display defaults for existing maps and the new canvas inline metadata without an older-client rendering guarantee. Opening/closing an existing map or refreshing its preview does not change its original tree; explicit save uses native fields. Existing canvas content, historical readers, checkpoints, epochs, pending bytes and message IDs remain intact. Canvas stays `aidcanvas-yjs` schema 1; rich text stays schema 3. Formatting and inline metadata retain canvas's existing whole-field LWW semantics, rather than per-character formatting CRDTs.

No database DDL, migration, backfill, old-format adapter or content deletion is introduced. Keep 0.1.31, its original package pins/patch/lockfile, databases, private assets, configuration and credential master key. Preserve later writes before rollback; earlier editors are not guaranteed to read new inline metadata or render current map styles.
