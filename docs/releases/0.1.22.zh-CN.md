# Doca 0.1.22

[English](0.1.22.md)

修复 PostgreSQL 18 从 0.1.20 文件夹结构升级时的启动失败。0.1.21 将新增 `revision`、`structure_json` 字段的 `NOT NULL` 目录记录误判成表约束变化，在执行升级前退出。

PostgreSQL 字段是否允许空值仍由字段元数据校验，表约束比较排除重复的 `pg_constraint` 记录。已有字段的空值约束变化仍需确认。已审定的默认值、原数据保留、事务回滚和兼容代际不变，无需手工执行 SQL 或重置数据库。

验证覆盖 PostgreSQL 17、18 的旧结构增量升级、并发及重复启动、已有空值约束变化拒绝、文件夹权限与邀请。使用实际发布的 0.1.20 镜像创建隔离 PostgreSQL 18 旧库，再用新镜像升级，检查用户、文件夹、成员、文档及分享链接记录保留。同时检查 SQLite 回归、默认全量测试、类型、文档和双架构镜像。

使用 `docker.io/smartdoca/doca:0.1.22` 或 `latest`（Linux amd64/arm64）。部署前备份数据库、文件存储和配置，保留原凭证主密钥和 Compose 项目名，启用新分享限制前更新所有宿主。启动会重新执行此前已回滚的增量升级。见[数据库结构演进](../database-schema-evolution.md)与[部署说明](../deployment.zh-CN.md)。

插件 SDK 保持 0.1.10。GitHub 标签 `v0.1.22` 附 Web 资源、部署包、校验文件和发行验证记录。
