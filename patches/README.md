# Dependency patches

The only active patch is `@mastra/memory@1.29.0`, registered in `pnpm-workspace.yaml` and the lockfile. It makes reflection read and validate the record actually committed by observation, preserving the observation cursor, token totals and observed message IDs. It changes neither stored rows nor schema and adds no adapter for another SDK version. `tests/ai-history.test.ts` checks real SDK reflection, retained messages and reopening without observing the same turns again.

The editor fixes now ship upstream: Slate 0.4.25 contains the DOCX fixes and Markdown 0.4.4 contains the KaTeX/lazy-PDF fixes. Doca installs their official npm artifacts without editor patch bindings. The obsolete editor patch files were removed after verifying the official artifacts and DOCX/PDF regressions; preceding releases and their matching patches remain recoverable from Git history. Local copies are retained under `artifacts/verification/npm-direct-2026-10-23/retired-editor-patches/`.

The DOCX scope covers directly assigned font family, font size, hex foreground/background colors, paragraph alignment, explicit off marks and table-cell marks, with online heading sizes, 16px body text, 1.6 line spacing and A4 defaults. Arbitrary inherited Word styles, complex sections and exact Word pagination remain outside the verified scope. `tests/document-pdf.test.ts` and `tests/document-pdf-access.test.ts` pass against official Slate 0.4.25. The actual browser export/reimport check passes three rich-text pages and one Markdown page, with math/image checks and zero source writes or page errors. See [the reviewed npm integration record](../docs/verification/issue-tracker-2026-10-21/npm-direct.md).

The Mastra patch cannot be removed by only raising `@mastra/memory`: inspected official 1.30–1.37 still pass the stale record to reflection; 1.38/1.39 contain a committed-record repair but require core exports absent from the locked `@mastra/core@1.66.0`. A broader SDK/storage upgrade needs a concrete API and persisted-data review under the repository compatibility rule. The existing protection remains required; no SDK upgrade, storage conversion or migration is made as part of the editor cleanup.
